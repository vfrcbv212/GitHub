# VolleyVision Local 0.3

Локальная Python-программа для видео волейбола 6×6: MOV/MP4, русский настольный
интерфейс, площадка и составы, редактор событий, проверяемая статистика и экспорт.
Подключены реальные модели людей, мяча и OCR, краткосрочный трекинг и кандидаты
касаний. Есть многокадровая галерея, три уровня геометрии, импорт измеренного
объектива и отдельные карты детекций/оценки времени. Необязательная обучаемая
GRU работает вторым проходом по временным наблюдениям; готовых проверенных
волейбольных весов для неё нет. После запуска анализ сам формирует отчёт,
без вопросов пользователю.

**Полная автоматическая волейбольная аналитика пока не готова.** Атаки, передачи,
касания блока, направления и результаты розыгрышей автоматически не классифицируются
с проверенным качеством. Без размеченных реальных данных показатели остаются
неизвестными. Редактор полезен для пилота, но не подменяет автоматизацию.
Таблица готовности — docs/FEATURES.md; проверки — docs/VALIDATION.md.

## Готовый переносимый Windows-пакет

Распаковать весь ZIP и запустить `VolleyVision.exe`. Python/PyCharm не нужны;
библиотеки и веса моделей включены. По умолчанию — CPU и режим без номеров.
Для RTX 3060 есть «Ускорение NVIDIA: подготовить автоматически»: скачивание
идёт в отдельную папку, GPU активируется только после проверки вычисления.
Инструкция, проверенный объём и ограничения — [docs/WINDOWS_PORTABLE.md](docs/WINDOWS_PORTABLE.md).
Windows-библиотеки и EXE проверены через Wine; целевой ПК/NVIDIA ещё не проверены.

## Windows: запуск из исходников

Нужен 64-битный Python 3.12: https://www.python.org/downloads/windows/.
В PowerShell из корня исходников, без администратора:

```powershell
.\scripts\Setup.ps1 -Compute cpu
.\.venv\Scripts\python.exe -m volleyvision.cli init D:\Volley\Match1 --title "Матч 1"
.\.venv\Scripts\python.exe -m volleyvision.cli fetch-models D:\Volley\Match1
.\scripts\Run.ps1 -Project D:\Volley\Match1
```

Если политика PowerShell запрещает .ps1, выполните команды вручную; глобальные
настройки безопасности менять не требуется:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install torch==2.13.0 torchvision==0.28.0 --index-url https://download.pytorch.org/whl/cpu
.venv\Scripts\python -m pip install -c requirements-windows.txt -e ".[cv,dev]"
.venv\Scripts\python -m pip check
```

Диагностика: `.\scripts\Diagnose.ps1` или
`.venv\Scripts\python -m volleyvision.cli diagnose --out diagnostics.json`.
Сохраняет GPU/VRAM/RAM, драйвер и проверку вычислений CUDA, без секретов.
Для GPU выберите поддерживаемый вашим драйвером и GPU вариант официальной
таблицы PyTorch: Setup.ps1 -Compute cu126 / cu130 / cu132. Универсальный выбор
без модели/драйвера не обещается. Отдельная случайная CUDA toolkit не нужна.
Проверены torch 2.13.0+cpu / torchvision 0.28.0+cpu на Linux; Windows/CUDA
ещё не проверены. Анализ при недоступной CUDA выбирает CPU с сообщением.

PyAV содержит локальные декодеры. Для proxy/клипов используется системный
FFmpeg, при отсутствии — imageio-ffmpeg из окружения. ffprobe необязателен,
часть метаданных без него берётся из PyAV. HDR tone mapping требует фильтров
zscale/tonemap: неподдержанная сборка сообщает ошибку. fetch-models — отдельная
явная загрузка весов; обычный анализ ничего не скачивает и не отправляет видео.

## Первый запуск

1. Импортировать оригинальные MOV/MP4; части выбираются по порядку. Оригиналы
не изменяются. Индекс PTS строится последовательно. Неизвестные разрывы записи
отмечены явно. Весь матч в RAM не загружается.
2. Ввести две команды. Номер и имя необязательны: в «Составах» можно оставить
«Без номера», каждая карточка получит отдельный постоянный ID. Одинаковые
известные номера соперников допустимы. Задать амплуа: связующий, диагональный, доигровщик, центральный,
либеро или неизвестно. profile.example.json показывает переносимый состав.
В настройках выбрать «По внешности, без номеров», «Внешность и номера» или
«По номерам с проверкой команды». Первый режим отключает OCR и сохраняет
память по нескольким кадрам человека. Подсказки после потери остаются
неподтверждёнными; качество на реальных игроках пока не измерено.
Инструкция и ограничения — [docs/IDENTITY.md](docs/IDENTITY.md).
В «Наша команда, образцы формы и либеро» выбрать нашу команду, двумя кликами
выделить участок футболки и сохранить несколько образцов для обеих команд.
Для либеро выбрать отдельный вариант формы и его карточку; отсутствие либеро
разрешено. Цветовые подсказки в галерее не подтверждают команду/личность.
3. Выбрать стоп-кадр → «Площадка». Колесо мыши — масштаб. Указать известные
пересечения линий, выбирая ориентир корта 18×9 м. Четыре невырожденные точки
дают оценку, но не доказывают точность: добавьте независимые контрольные точки.
Без них матрица остаётся черновым наложением, метрическая аналитика отключена.
Все внешние углы не обязательны. Альтернатива точкам — видимые подписанные
отрезки (лицевая/трёхметровая/боковая): для метров нужны независимые линии двух
направлений и отдельная контрольная точка. Невидимые углы не становятся
наблюдениями. При недостатке ограничений можно вручную обозначить
видимые приблизительные зоны 1–6 с командой и интервалом; без зон остаются
координаты видео. Отдельно указать видимый пол, поиск людей, поиск мяча
(включая воздух), преграды и сетку. Верх сетки не точка пола. Область полотна
сетки и мягкая область судьи не доказывают касание сетки и не исключают
проходящего игрока. По заданным ориентирам можно предложить небольшое
уточнение совмещения по белым линиям;
это не полный автоматический поиск корта. Подробности — docs/GEOMETRY.md.
4. Предварительный проход собирает изображения людей; в режимах с номерами
может также искать номера по всей записи, включая поздние кадры.
Галерея показывает все сохранённые кропы и времена выбранного фрагмента,
голоса OCR и причины неопределённости; по образцу можно перейти к исходному
кадру. Выберите команду/игрока и интервал либо оставьте личность неизвестной.
Несколько непересекающихся фрагментов можно явно связать с одним игроком;
противоречивые одновременные привязки не назначаются молча. Судья/запасной
учитывается отдельно. Подробности — docs/GALLERY.md.
Надёжное объединение личности после потери пока не готово: второй проход
сохраняет гипотезы, не переносит имя по ближайшей позиции.
5. «Запустить анализ → отчёт». После старта вопросов нет. Неизвестные значения
сохраняются, отчёт exports/automatic/report.html создаётся даже при пустой части
статистики. Завершённый стартовый проход переиспользуется при тех же настройках.
Ручной счёт необязателен: в «Ручной счёт и партии» создать/выбрать партию,
внести отметку после очка или итог партии (итог разрешён без времени).
«Начало партии» означает явно заданные 0:0; при записи с середины партии
не включать этот флажок. Отметки можно выбрать в таблице, исправить или убрать.
Сверка показывает уменьшение счёта, перекрывающиеся розыгрыши и недостающие
связи с очками. Между отметками не выдумываются авторы, действия и времена.
Победителя известного розыгрыша можно внести/исправить отдельно, указав партию.
Подробный сценарий — docs/SETUP.md.
6. При желании исправить события. Space — пауза; стрелки — соседний реальный
кадр по PTS; N — событие; Ctrl+Z — отмена. Есть 0.25×/0.5× и поиск непроверенных.
Просмотр без звука. Рамки имеют отметку временного смещения наблюдения.
7. Экспортировать automatic, confirmed или preliminary. CSV UTF-8 BOM с «;»,
XLSX, JSON, HTML, SVG и MP4 отдельных эпизодов. Клипы без звука, не заполняют
разрывы записи. При экспорте клипов создаётся и montage.mp4: 1280×720, без звука; соседние подборки могут перекрываться по времени.

Время события — секунды от первого видеокадра исходника. PTS/time_base
сохранены. Proxy проверяется по числу кадров и времени (допуск 2 мс).
Клип использует полуоткрытый интервал [start,end) и JSON-manifest с SHA и
первым исходным кадром. Гомография применяется только к полу, не к мячу в
полёте или рукам в прыжке. В мастер можно загрузить измеренную pinhole/fisheye
модель K/D для того же размера и ориентации: коррекция используется при оценке
пола и обратном наложении линий, исходник сохраняется. Программа не определяет
дисторсию iPhone 0.5× по одной картинке; без измерений тип объектива неизвестен.

В HTML/JSON дополнительно разделены карта числа детекций и оценка времени
присутствия. Они построены в координатах видео по наблюдениям людей и соседним
детекциям временной траектории. Пропуски не заполняются. Это не эффективность,
не точная карта стоп на полу и не доказательство отсутствия игрока в пустой
ячейке. Персональное время требует явной интервальной привязки; неподтверждённые
и противоречивые личности показываются отдельно. Несовместимые фильтры действий
не превращаются в фильтры карты наблюдений; подробные правила в docs/METRICS.md.

## Пакетный запуск без вопросов

```powershell
.venv\Scripts\python -m volleyvision.cli import D:\Volley\Match1 D:\Video\part1.MOV D:\Video\part2.MOV
.venv\Scripts\python -m volleyvision.cli load-profile D:\Volley\Match1 profile.example.json
.venv\Scripts\python -m volleyvision.cli analyze D:\Volley\Match1 --config config.example.json
.venv\Scripts\python -m volleyvision.cli report D:\Volley\Match1 --mode automatic
```

Калибровка принадлежит конкретному исходнику текущего проекта и не переносится
с другого матча автоматически. Состав можно переиспользовать. Сохранённый
ракурс текущего файла не требуется размечать повторно. config.example.json —
параметры обработки, не калибровка. SQLite хранит настройки; JSON-снимок
выгружается как project-events.json. report --filters filters.json поддерживает
set_id, team_id, player_id, rotation, direction, type, outcome, lineup_id и зоны;
матч выбирается папкой проекта, степень подтверждения — --mode.

## Необязательная модель действий

В «Подключить обученную модель действий» можно выбрать локальный артефакт GRU;
его путь сохраняется в проекте. Основной анализ при наличии артефакта выполняет
второй проход по последовательностям наблюдений. Отдельная команда:

```powershell
.venv\Scripts\python -m volleyvision.cli infer-actions D:\Volley\Match1 RUN_ID D:\Experiments\actions\versions\VERSION
```

По умолчанию типы действий остаются гипотезами и видны в preliminary; они не
заполняют основные таблицы automatic. Автоматическое принятие требует отдельной
явной политики, проверенной по реальной отложенной разметке событий. Ни softmax
score, ни обучение на синтетике не доказывают точность. Тип действия сам по себе
не определяет игрока, направление, исход или автора очка. Без артефакта базовая
программа работает; неподдерживаемые действия остаются неизвестными. Обучение,
checkpoint и политика описаны в docs/TEMPORAL.md; подготовка окон из проекта —
в docs/TEMPORAL_EXPORT.md. Проверенных реальных весов действий сейчас нет.

## Перенос, отмена и продолжение

Проект — project.sqlite, media/, models/, cache/, exports/. Оригиналы могут
лежать снаружи; после переноса путь восстанавливается с проверкой полного SHA256.
Для переносимости лучше держать копии внутри media/. Перед обычным копированием
SQLite закройте приложение; для открытой базы есть Project.backup.
Не удаляйте -wal открытой базы. Снимок JSON содержит и ручной, и автоматический
слой; рабочая база остаётся главным источником.

Анализ сохраняет каждый обработанный PTS. Повторный запуск продолжает с него;
после checkpoint новый сегмент траекторий не получает старую личность по
близости. Частичный импорт сохраняется, но повторное индексирование декодирует
сначала. Задание complete повторно не обрабатывается. SHA модели, параметры и версии
калибровочных профилей входят в кэш. Отдельная стадия setup_complete сохраняет
результат предварительного прохода; основной запуск завершает следующие стадии.
Смена галерейной привязки пересчитывает карты и второй проход без автоматической
смены личности у остальных траекторий. Ручные исправления не стираются при новом запуске.

## Демонстрация и разработка

```powershell
.venv\Scripts\python -m volleyvision.cli demo D:\Volley\SyntheticDemo
.venv\Scripts\python -m volleyvision.cli gui D:\Volley\SyntheticDemo
.venv\Scripts\python -m pytest -q
```

Демо: синтетическое VFR-видео и заранее известные события, включая отрицательную
эффективность и групповой блок. Это проверка формул, не точности распознавания.
Linux: python3.12 -m venv .venv, CPU torch/torchvision из официального индекса,
затем `.venv/bin/python -m pip install -c requirements-windows.txt -e '.[cv,dev]'`.
Headless GUI: `QT_QPA_PLATFORM=offscreen .venv/bin/python scripts/test_gui_workflow.py`.
Переносимый Windows EXE собирается через GitHub Actions; инструкция — docs/WINDOWS_PORTABLE.md. LLM не нужна.

Нет CUDA → CPU/diagnose; нет исходника → восстановить путь; нет весов → fetch-models;
кодек/HDR не поддержан → cache/last-error.txt и FFmpeg log; мало точек → режим
видео; мяч потерян → пропуски, без выдуманного очка. Не удаляйте разметку.

Разработка: AGENTS.md и docs/FEATURES.md. Словарь — docs/METRICS.md;
источники/условия — docs/MODELS.md; обучение детектора — docs/TRAINING.md;
геометрия — docs/GEOMETRY.md; галерея — docs/GALLERY.md; временная модель —
docs/TEMPORAL.md и docs/TEMPORAL_EXPORT.md.

Резервный комплект исходников/документов/истории и синтетического примера:
`python scripts/checkpoint.py --demo --verify` (по умолчанию work/VolleyVision-checkpoint.zip).
Он не включает окружение, веса или частные видео. Архив в облачной временной
папке сам по себе не гарантирует долговременную сохранность.
