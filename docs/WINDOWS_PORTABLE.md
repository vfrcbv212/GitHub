# Переносимый Windows-пакет v0.3

Распаковать **весь** ZIP и запустить `VolleyVision.exe`. Нужна Windows x64;
Python, PyCharm и установка библиотек на ПК не нужны. В `runtime` находится
официальный CPython 3.12.10 с Windows wheels, в `models` — детектор и OCR.
MSVC-библиотеки из официального PySide6 wheel также доступны рядом с Python,
поэтому предварительная установка Visual C++ Redistributable не требуется.
Первый запуск создаёт `Projects/Match1`, выбирает режим без номеров и копирует
проверенные веса в проект. Новые проекты также используют встроенные модели.
Существующие пользовательские модели не заменяются. `Демо.cmd` показывает
синтетический пример с заранее внесёнными событиями.

Для анализа без номеров: импортировать короткий MP4/MOV → составы → разметка
видимой площадки → предварительный проход → первоначальные карточки в галерее →
анализ/отчёт. Отчёт: `Projects/Match1/exports/automatic/report.html`.
Память внешности даёт гипотезы; полноценная автоматическая статистика игры
и надёжный ReID пока не готовы. Подробности в FEATURES.md и IDENTITY.md.

## Необязательное ускорение NVIDIA

Кнопка «Ускорение NVIDIA: подготовить автоматически» скачивает точные
`torch==2.13.0`/`torchvision==0.28.0` с официального CUDA 12.6 index в отдельную
папку. Требуется от 6 ГБ свободного места. CPU-пакеты не изменяются. Только
успешный запуск CUDA-операции создаёт READY.json. После перезапуска GPU
проверяется отдельным процессом; при ошибке используется исходная CPU-сборка.
Никакие драйверы, глобальный Python или CUDA Toolkit не устанавливаются.
Подготовка требует интернета. Исполнение на NVIDIA и производительность
на конкретном компьютере нужно проверять фактическим запуском.

## Что проверено

118 тестов прошли на Linux CPU и 118 — на настоящем Windows CPython/Windows
библиотеках под Wine 10.0. Windows GUI-пакет использует Qt/PySide6 Essentials
6.8.3; исходное Linux-окружение использует 6.12.0. Qt 6.12 Windows в Wine не
загрузил системный icuuc.dll, поэтому для переносимого пакета выбран 6.8.3.

Именно VolleyVision.exe выполнял: локальные SHA моделей → 512 нейропризнаков →
OCR «17» → synthetic video → analyze → HTML/XLSX/JSON → окна составов, формы,
счёта, калибровки и галереи. Образец формы и счёт сохранены. Проверены русские
имена файлов/пути с пробелами. Также выполнен обычный запуск без аргументов:
создание проекта, начальная настройка, видимое окно и штатное закрытие.
Проверка Wine не заменяет нативную Windows/NVIDIA и проверку реального
волейбола. При сборке через GitHub Actions результат нативного Windows
прогона включается в docs/validation/native-windows-ci.json.

## Воспроизведение сборки разработчиком

- CPython: официальный NuGet python/3.12.10, каталог tools.
- Windows wheels: runtime-requirements.txt и portable-constraints.txt в
  packaging/windows; CPU Torch — официальный index download.pytorch.org/whl/cpu.
  filterpy 1.4.5 поставляется чистым Python wheel.
- Зависимости устанавливаются Windows pip в этот CPython. Для Linux-прогона
  используется Dockerfile.wine, Wine запускается с uid владельца каталога build,
  DISPLAY от Xvfb, LANG/LC_ALL=C.UTF-8. В Wine OpenMP требует
  KMP_AFFINITY=disabled и KMP_TOPOLOGY_METHOD=flat; это не настройки целевого ПК.
  Нужный proxy CA монтируется отдельно; в пакет он не попадает.
- launcher.c компилируется MinGW64: `-municode -mwindows -static-libgcc -Os -s`.
  EXE вызывает только вложенный pythonw.exe: `-I -B -X utf8`, затем bootstrap.
- scripts/build_windows_portable.py принимает --runtime, --launcher, --models,
  --out и --zip. Формирует SHA manifest BUILD.json; проверяет SHA весов/ZIP CRC.
  Исходники лаунчера, программы и уведомления о лицензиях включены в ZIP.

Сборка не подписана. Она не меняет защиту Windows и не требует администратора.
Ошибки запуска пишутся в `%LOCALAPPDATA%/VolleyVision/Logs/startup-error.txt`;
ошибки анализа — в `cache/last-error.txt` проекта. Автоподготовка NVIDIA имеет
отдельный nvidia-setup.log. Сетевых обращений при обычном анализе нет.
