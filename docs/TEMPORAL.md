# Необязательная временная модель действий

Добавлен настоящий обучаемый GRU и локальный второй проход по сохранённым
наблюдениям. **Готовые волейбольные веса не поставляются.** Обучение на синтетике
проверяет код, а не распознавание игры. Пока нет реальной разметки и отдельной
проверки событий, результаты модели — только гипотезы. Основные automatic
таблицы не наполняются ими. Ручная проверка каждого нового матча не требуется:
проход заканчивается с неопределённостями и отчётом без вопросов.

Модуль использует временную последовательность, не один кадр. Он не определяет
личность, команду, победителя, исход атаки, направление на корте или касание
пола. Даже принятый тип `attack` не означает `kill` и не создаёт очко.
`block_attempt` и `block_touch` — разные классы; `block_point` специально не
выводится этой головой. Истинность контакта и надёжность каждого класса ещё
нужно измерить на эталоне.

## Формат данных

Открытый JSON, `schema_version=1`, обязательные `data_kind=real|synthetic`,
`feature_names`, `window_seconds`, `stride_seconds`, список `windows`.
`feature_names` должен в точности совпадать с `temporal.FEATURE_NAMES`.
Окно имеет поля:

```json
{
  "id": "match1-0001",
  "match_id": "match1",
  "source_id": "part1",
  "view_id": "camera1",
  "source_sha256": "полная SHA256 исходного видео",
  "times": [10.0, 10.1, 10.2, 10.3],
  "anchor": 10.2,
  "label": "attack",
  "reviewed": true,
  "features": ["здесь 3–256 числовых строк по 18 признаков"]
}
```

В этом примере `window_seconds` было бы 0.3; реальный стартовый профиль —
2 секунды с шагом 0.25 секунды. Anchor всегда **фактическое время среднего
наблюдения** `times[len(times)//2]`, не номер кадра / заявленные 60 FPS.
Числовые признаки извлекаются из `Project.observations(run_id)`:

```python
from volleyvision.temporal import FEATURE_NAMES, observation_windows
for window in observation_windows(project.observations(run_id), width, height):
    # Сопоставить с проверенной разметкой действий у window['anchor'];
    # присвоить id, match_id, source_id, label, reviewed.
    # Это работа подготовки эталона, не штатный сценарий анализа матчей.
    pass
```

18 признаков: dt, видимость/центр/размер мяча, экранная скорость и её маска,
факт выборки людей, видимость/центр/размер соседнего человека, расстояние,
число кандидатов мяча и статус геометрии. Координаты изображения нормированы
размером исходного повёрнутого кадра, метры не выдумываются. Соседний человек
не считается участником контакта. Несколько мячей — неопределённость;
пропуски не интерполируются; экранная скорость не равна физической скорости
мяча. Маски отличают неизвестное от нулевого движения.

Классы: none (фон), serve, receive, set, attack, tip, block_attempt, block_touch,
dig, cover, freeball, rally_start, rally_end. Нужны фоновые окна и хотя бы один
положительный класс. `reviewed=false`, NaN, несогласованные времена и неизвестные
классы отвергаются. Окна без полного знания метки не превращать в `none`:
отсутствие разметки не доказывает отсутствие действия.

Train, validation и последующую оценку политики разделять **по матчам**.
Также запрещено пересечение source_id и SHA исходников, если они указаны.
Не переименовывать один матч ради обхода проверки. Сохранять ракурс/view_id и
оценивать новые ракурсы отдельно. Нормализация считается только по train.

## Обучение и продолжение

```powershell
.venv\Scripts\python scripts\train_temporal.py train D:\Labels\train.json D:\Labels\validation.json D:\Experiments\actions --epochs 20 --device auto
# Продолжить из последней завершённой эпохи:
.venv\Scripts\python scripts\train_temporal.py train D:\Labels\train.json D:\Labels\validation.json D:\Experiments\actions --epochs 40 --resume --device auto
```

Есть --hidden-size, --layers, --batch-size, --learning-rate, --seed. Checkpoint
сохраняется атомарно после эпохи: веса, optimizer, RNG, параметры и SHA обоих
наборов. Прерывание в середине эпохи повторяет её, не весь эксперимент. Смена
данных или параметров требует новой папки. `checkpoint.pt` — собственное
доверенное локальное состояние, загружается только для resume. Модель для
обычного анализа загружается с `weights_only=True`.

`epoch-*.json` показывает классификацию окон, **не** полноту событий или
статистику матча. В `versions/<content-id>/` публикуются неизменяемые `model.pt`
и `manifest.json`: SHA весов и manifest, архитектура, словарь, нормализация,
длительность/шаг окон, происхождение и отключённая политика принятия.
Старая версия не перезаписывается. Манифест/веса проверяются при загрузке.
Только импорт этого модуля не импортирует PyTorch; без модели базовая программа
и отчёты работают. Скачивание и облачные запросы отсутствуют.

## Политика автоматического принятия

Большой softmax score не означает вероятность правильного события. По умолчанию
даже score 0.999 даёт `hypothesis`, review остаётся `unreviewed`. Автоматическое
принятие включается только явной отдельной калибровкой политики на реальном
отложенном наборе событий, без пересечения с train/validation:

```powershell
.venv\Scripts\python scripts\train_temporal.py calibrate D:\Experiments\actions\versions\VERSION\manifest.json D:\Labels\policy.json D:\Experiments\policies --rules D:\Labels\rules.json --enable-automatic
```

`policy.json` содержит те же проверенные окна и дополнительно:

```json
{
  "coverage_verified": true,
  "annotation_intervals": [
    {"source_id":"part3","start":1.0,"end":119.0,"reviewed":true,
     "types":["serve","receive","set","attack","tip","block_attempt","block_touch","dig","cover","freeball","rally_start","rally_end"]}
  ],
  "events": [
    {"source_id":"part3","start":12.345,"type":"attack","reviewed":true}
  ]
}
```

Все события перечисленных типов внутри заявленных интервалов должны быть
размечены. Нужны также фоновые окна: их отсутствие делает precision ложным.
Проверяется плотное покрытие интервалов окнами с объявленным шагом. Нельзя
установить coverage_verified только ради запуска. Это не полнота всего матча;
неразмеченные интервалы не входят в оценку.

Проверяется не только классификатор: применяются временной NMS и точное правило
сопоставления событий (один-к-одному, один исходник/тип, допуск по времени).
Для каждого типа сохраняются TP/FP/FN, event recall, размер принятой выборки,
ошибки и их верхняя граница Wilson 95%. Текущие стартовые правила: score>=0.9,
отрыв >=0.2, минимум 3 наблюдения мяча и доля >=0.4, разрывы <=0.5 с,
NMS 0.6 с, допуск времени 0.25 с, минимум 30 принятых примеров и верхняя граница
доли ошибок <=0.1, полнота событий класса >=0.5. Последний порог задаётся
min_event_recall в rules.json: высокая precision при пропуске большинства
эталонных событий не разрешает принятие. Это инженерные настройки, **не согласованные критерии**
пригодности и не обещанные проценты. Параметры задаются rules.json; изменение
правил после проверки отключает принятие до новой оценки.

Synthetic, отсутствие полного эталона, редкий класс без достаточной выборки,
пропущенные интервалы или низкая полнота не превращаются в успех. Класс без
подтверждённой политики не попадает в основные таблицы; его можно посмотреть
в предварительном отчёте. Политика привязана к SHA весов и всей схеме окон.
Новый ракурс может дать другую ошибку; качество за пределами пилота не доказано.

## Локальный второй проход

```powershell
.venv\Scripts\python scripts\train_temporal.py infer D:\Volley\Match1 RUN_ID D:\Experiments\actions\versions\VERSION\manifest.json
```

API: `infer_project(project, run_id, artifact_dir, policy=None, progress=None,
cancel=None)`. Детекция повторно не запускается. Сохранённые временные окна
используют оригинальные PTS среднего кадра. Тип, актёр, команда, результат и
геометрия независимы; этот модуль заполняет только тип. Исходы/победитель/
направления остаются неизвестными. Автоматические предложения и ручной слой
разделены, повторный проход не стирает правки.

Ключ кэша включает manifest/политику/схему окон, прогресс исходного задания
наблюдений и полный упорядоченный снимок интервальных привязок галереи с SHA.
Привязки накладываются на копию потока наблюдений через индекс интервалов для
каждой траектории: поздняя правка роли судьи/запасного сразу исключает его из
контекста соседнего человека. Исходные детекции не изменяются, детекторный кэш
не сбрасывается. Последняя привязка побеждает только внутри своего включительного
интервала; SQL-запросов на каждого человека нет. Личность/команда/исход действия
этим не подтверждаются и по-прежнему остаются независимыми неизвестными.
Законченное неизменённое задание не пересчитывается. При выборе A→B→A
выбранные базы событий A восстанавливаются из SQLite без повторного GRU;
ручные слои остаются. Отбор NMS выполняется до ограничения размеченными
типами/интервалами и порогом принятия, одинаково в оценке и исполнении.
Политики старого алгоритма отбора не разрешают принятие. Смена профиля,
сессии камеры/сегмента трекинга обрывает окно; смена ID мяча обнуляет скорость.
При отмене
сохраняется каждое обработанное окно; после запуска восстанавливается
необходимый ограниченный контекст, уже завершённые GRU-окна не вычисляются
повторно. Предложения и глобальный NMS хранятся в SQLite (`temporal_candidates`,
`temporal_selected`), изображения и весь видеоматч в память не загружаются.
При перерыве в NMS его дешёвая сортировка повторяется по сохранённым кандидатам,
сохраняя решения через границы chunks/resume. Старые автоматические-only
предложения новой версии, которых больше нет, исключаются; ручные слои остаются.

Синтетические тесты реально обучают GRU и продолжают из checkpoint, проверяют
кэш/отмену/возобновление и запрет автоматического принятия по одним scores.
Они не являются доказательством распознавания волейбольных действий. Для этого
по-прежнему нужны оригинальные видео и проверенный эталон новых матчей.

## Реально выполненная проверка этой реализации

Linux/CPU: `OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 .venv/bin/python -m pytest -q
tests/test_temporal.py` — проходит в общем прогоне (validation/v02-tests.xml). Проверены неизменяемость версий и SHA,
реальное обучение GRU/продолжение, запрет принятия raw-score, временные пропуски,
раздельность матчей, оригинальный PTS, сохранение ручной правки, отмена/resume
без повторного GRU, глобальный NMS и кэш/изменённый прогресс исходных наблюдений.
Отдельно `scripts/train_temporal.py train` реально выполнил synthetic epoch0
и `--resume` epoch1; созданы две независимые версии с отключённым принятием.
Журнал: work/temporal-train-smoke.log. В игрушечном примере 4/8 окон определены
правильно; это проверка подключения кода, не измерение качества игры.

Последняя интеграционная проверка: роль изменена в галерее после первого
временного прохода → новый временной cache key, маска person_visible меняется
с 1 на 0 для судьи, исходные наблюдения и detector job неизменны. Проверены
приоритет пересекающихся интервалов и отсутствие влияния привязок другого run.
