# Разметка и оценка

Обученной модели типов волейбольных действий пока нет. Человек/мяч/OCR работают
с готовыми общими моделями. Кандидат контакта не подменяет атаку или блок.
Для специализированной модели нужны оригинальные последовательности и
эталонная разметка. Универсальное достаточное число кадров не устанавливается:
сначала пилот и анализ ошибок по типам действий и ракурсам.

1. Запустить анализ и взять job.id из вывода CLI.
2. Экспортировать кадры с рамками-предложениями:

```powershell
.venv\Scripts\python scripts\annotations.py D:\Volley\Match1 RUN_ID D:\Volley\Labels --every 2
```

3. Проверить COCO в CVAT (open source, возможен локальный запуск): добавить
пропущенных людей/мяч, удалить ложные рамки. category_id person=1, sports ball=37.
Не рисовать мяч там, где он не виден. Контакты и действия размечать отдельно
по последовательности. reviewed=false запрещает обучение до проверки.
4. Сохранить match_id и view_id в images после обратного экспорта из CVAT.
Соседние кадры одного матча не разделять между train/validation/test. Делить
по матчам, желательно залам/ракурсам. Тест не использовать для порогов и обучения.
5. Обучить детектор в отдельном каталоге:

```powershell
.venv\Scripts\python scripts\train_detector.py D:\Labels\train\annotations.json D:\Labels\val\annotations.json D:\Volley\Match1\models D:\Volley\Experiments\v1 --epochs 10 --device auto
```

--resume продолжает с последней завершённой эпохи. Checkpoint включает модель,
optimizer, epoch, RNG и SHA разметки. Прерывание в середине эпохи потребует
повторить её. Смена разметки требует нового эксперимента. Ctrl+C сохраняет
предыдущий checkpoint. Скрипт запрещает пересечение match_id, но не защищает
от неверно названных матчей. Валидация — precision/recall/F1 при score>=0.5,
IoU>=0.5 отдельно для людей/мяча; это не COCO mAP и не качество событий.

6. После проверки на отдельных тестовых матчах активировать выбранные веса:

```powershell
.venv\Scripts\python scripts\activate_model.py D:\Volley\Experiments\v1\epoch-009.pth D:\Volley\Match1\models
```

Архитектура и 91 COCO-выход должны сохраняться. Старые веса и
manifest-before-*.json остаются. Откат — восстановить прежний manifest.json.
Новая SHA меняет кэш; ручные исправления не стираются.

## События

JSON описан в domain.py/demo.py. Размечать интервалы розыгрышей, время и тип
действий; по отдельности — участника, команду, зоны, направление и результат.
Неизвестное — null с причиной. Групповой блок — одно событие с участниками.

```powershell
.venv\Scripts\python scripts\evaluate_events.py truth.json predictions.json evaluation.json --tolerance 0.25
```

Сопоставление взаимно однозначное (Hungarian), одного типа и исходника, по
расхождению времени начала <=0.25 с. Допуск не является обещанной точностью.
FP и FN считаются отдельно; точность полей условна на совпавших событиях,
их определённость выводится рядом. Нужна полнота событий по эталону: хороший
результат на одном событии при пропуске остальных непригоден. При полном отказе
precision=null, recall=0 при непустом эталоне — это не успех автоматизации.

Для пилота измерить ID switches, неверные переносы личности, OCR по нескольким
кадрам, отклонение статистики, время начальной настройки, число вопросов после
запуска (должно быть 0), скорость/RAM/VRAM. На реальном видео это не измерено.
Автоматического IDF1/HOTA сейчас нет; для TrackEval нужен эталон траекторий.
Для типов действий теперь есть отдельный обучаемый GRU и локальный второй
проход: [TEMPORAL.md](TEMPORAL.md). Экспорт наблюдаемых окон для разметки описан
в [TEMPORAL_EXPORT.md](TEMPORAL_EXPORT.md). Это работающий код обучения,
но готовых проверенных волейбольных весов по-прежнему нет. Касания блока,
надёжный ReID и исходы требуют отдельных данных и проверки. Критерии пригодности предложить после пилота
раздельно по действиям/ракурсам/обзору. Согласованных порогов сейчас нет.
