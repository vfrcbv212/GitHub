# VolleyScope Native 0.2

Экспериментальная локальная программа на C++20 / Qt 6 / ONNX Runtime.
Python для работы приложения не нужен. Видеозаписи и карточки людей остаются
на компьютере. Основные модели: YOLO11s-pose, VballNetV4c, OSNet MSMT17;
необязательная подсказка номеров — PP-OCRv4.

## Запуск

Скачайте Windows ZIP из Releases, распакуйте **всю папку** и запустите
`VolleyScope.exe`. В ZIP входят библиотеки, FFmpeg и модели. Переносить только
EXE нельзя. Требуется Windows 10/11 x64. Для GPU используется DirectML / DirectX 12;
CUDA и Python устанавливать не требуется. При невозможности создать GPU-сессию
приложение пробует CPU и сообщает об этом в строке состояния.

## Первое видео

1. Нажмите **Открыть видео**. Поддерживаются обычные записи MP4/MOV/MKV.
2. Откройте **Площадка и состав**. Видимые границы и линии размечаются точками.
   Для сетки можно указать много точек. Антенна — низ у верхней кромки сетки и верх.
   Судья — два угла прямоугольника. Мяч — центр и край круга.
3. Добавьте основные составы A и B, запасных и либеро. У каждого человека один
   постоянный ID. Укажите, кто начинает на площадке и кто является запасным.
4. Выберите строку игрока, инструмент **Образец игрока**, отметьте два угла вокруг
   одного человека и нажмите **Сохранить образец**. Несколько изображений с разных
   сторон можно прикрепить к одному ID. Запасного без изображения можно добавить
   заранее; когда он появится, добавьте образец к его существующей карточке.
5. Выберите ближнюю команду **в начале записи**. Две независимые настройки позволяют
   использовать разную одежду, общую форму, номера на форме или номера без общей формы.
6. Сохраните разметку и нажмите **Начать анализ**.

Разметка кадров необязательна. Для устойчивой принадлежности к игре/команде и
постоянных номеров рекомендуется первоначальный состав с образцами. Без состава
автоматическое создание ограничено первыми восемью секундами и шестью людьми
на команду; позже неизвестные люди требуют уточнения и не расходуют новые номера.
Невидимого человека программа не рисует, но его карточку не удаляет.

В редакторе доступны текущий кадр и десять кадров из разных частей записи.
Правый клик удаляет последнюю точку; точки можно перетаскивать. Невидимые углы
не требуются. Настройки одежды не меняют команду зарегистрированного игрока.

## Плеер

- **▶ / Ⅱ**, пробел — воспроизведение и пауза просмотра. Анализ может продолжаться в фоне.
- **−5 / +5 секунд**, стрелки клавиатуры — перемотка.
- **◀ Кадр / Кадр ▶**, клавиши `,` / `.` — покадровые шаги на паузе.
- Ползунок — переход к любому месту. Анализ переносится к выбранному времени;
  память игроков сохраняется. Пропущенные перемоткой участки можно обработать позже.
- Скорость просмотра **0,25×–10×**. Если нужные наложения ещё вычисляются, плеер
  ожидает их; ускорение воспроизведения не означает такой же скорости нейросетей.
- **Смена сторон** — отметить переход команд на другие половины в текущий момент.
  Сами команды в карточках людей сохраняются. Для начала удобнее отдельное видео партии.
- **Остановить анализ** — завершить вычисления, сохранив готовые кадры и карточки.
- **Сохранить видео** — полный экспорт с начала до конца, наложениями и исходным звуком.
  При полном кеше измеренных результатов модели повторно не запускаются.
- **Открыть результат** — открыть готовый MP4 внешним плеером.

В окне уточнения есть **Больше не уточнять автоматически**. Эту настройку можно
включить обратно в главном окне. Неуверенная личность остаётся неподтверждённой,
а не превращается в нового «Игрока 100». Узнавание людей в одинаковой одежде после
долгой потери не гарантируется. Необязательное OCR номера — дополнительная
подсказка, а не доказательство личности.

## Проверки и ограничения

Нейросети поз и мяча получают каждый декодированный кадр выбранного участка.
ReID и OCR запускаются при возвращении, перекрытиях и периодически для обновления
образцов, чтобы не выполнять лишние вычисления. Поиск мяча использует девять кадров,
траекторию, близость к кистям и фильтр неподвижных/медленных ложных кандидатов.
Неподвижные и катящиеся запасные мячи всё ещё могут требовать ручного указания игрового.

Автоматические семантические линии площадки/сетки/антенн не добавлены: здесь они
задаются вручную. Непрерывное самообучение весов на непроверенных предсказаниях
не включено. Галерея внешности — память наблюдений, а не такое переобучение.

Цель 30 FPS на GPU должна подтверждаться реальным замером. Результаты проверки
логики на искусственных траекториях и работы на CPU не являются проверкой точности
на матче или доказательством 30 FPS. Скорость экспорта из готового кеша указывается
как `cached` и не является скоростью распознавания. Вывод готового MP4 пока требует
постоянной частоты кадров; VFR не экспортируется с молчаливой подменой временных меток.

## Сборка из исходников

CMake 3.22+, C++20, Qt 6.6+ (Widgets, Multimedia, Network, Sql, Concurrent),
ONNX Runtime. Для Windows используется пакет Microsoft.ML.OnnxRuntime.DirectML
1.24.4 + Microsoft.AI.DirectML 1.15.4. Готовый workflow собирает и проверяет Windows ZIP.

```sh
cmake -S native -B build -DONNXRUNTIME_ROOT=/path/to/onnxruntime
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

`native/tools/prepare_models.py` — **инструмент сборки**, не зависимость приложения.
Он проверяет публичные исходные веса и экспортирует ONNX. Правила и контрольные
суммы закреплены в коде. Источники и лицензии: [SOURCES.md](SOURCES.md).
